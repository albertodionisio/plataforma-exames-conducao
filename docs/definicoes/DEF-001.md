# DEF-001 — Página principal de definições

## Objectivo
Criar a página principal de Definições do ESTRADA, com identidade visual coerente com a aplicação, navegação interna e estrutura preparada para receber funcionalidades futuras.

## Implementação no repositório
- Página: `public/definicoes/index.html`.
- Estilos responsivos: `public/definicoes/definicoes.css`.
- Navegação acessível: `public/definicoes/definicoes.js`.
- Teste estrutural: `scripts/testar-definicoes.js`.
- Validação automática: `.github/workflows/testar-definicoes.yml`.
- Integração no menu principal: `index.html`, com ligação «Definições» depois de «Planos».

## Categorias incluídas
1. Personalização: aparência, som e idioma.
2. Conta e segurança: perfil, palavra-passe, dispositivos e sessão.
3. Aprendizagem: histórico, perguntas guardadas e progresso.
4. Subscrição e pagamentos: ligação para a rota existente de planos e indicação das funções que dependem de conta/pagamentos.
5. Ajuda e suporte: perguntas frequentes, contacto e reporte de problemas.
6. Sobre o ESTRADA: aplicação, termos, privacidade e fontes legais.

## Limites desta entrega
- Os itens ainda sem implementação são apresentados como «A preparar», «Em preparação» ou dependentes de conta/serviços. Não devem ser tratados como funcionalidades activas.
- A página usa SVG inline, sem emojis, e inclui atalhos para as seis categorias, foco visível, navegação por teclado e adaptação a ecrãs pequenos.
- O build copia a pasta `public/` integralmente para `dist/`, incluindo a página e os seus recursos em `dist/public/definicoes/`.
- A página pode ser aberta directamente em `/public/definicoes/` no endereço publicado.
- A ligação ao menu principal foi integrada no commit `c9aca250b3ce0c49f3d09f220377552a9368394a`.

## Validação automática
O workflow dedicado executa:
- verificação da sintaxe JavaScript;
- teste dos seis destinos internos e categorias;
- verificação dos links de regresso e planos;
- verificações básicas de acessibilidade e media queries;
- build Netlify e confirmação dos três ficheiros em `dist/`.

O workflow foi actualizado para também ser accionado quando `index.html` mudar, tanto em `push` como em `pull_request`. A execução após esta alteração deve ser consultada no GitHub Actions; não se deve registar aprovação antes de o resultado estar concluído com sucesso.

## Validação visual e critério de conclusão
A validação visual no navegador continua necessária para confirmar a experiência real em ecrã pequeno: abrir o menu, entrar em Definições, percorrer as seis secções e regressar à aplicação. A tarefa só deve ser marcada como totalmente concluída depois de confirmar o workflow com sucesso e realizar essa validação visual.
